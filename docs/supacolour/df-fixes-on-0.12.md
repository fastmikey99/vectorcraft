# DF fixes on VectorCraft 0.12

Status: local ports complete; Fira host delivery pending, 17 October 2026. Base: `a417e806`; branch:
`codex/df-fixes-on-0.12`. Each numbered port is a separate commit. No customer
files, font binaries, Adobe application material or external reviews are used.
The local `plan/` instructions referenced by AGENTS.md are absent in this worktree.

## 1. Direct ICC CMYK conversion — aff6c213

**Ported.** 0.12 still converted through display sRGB/Lab. Restored `to_cmyk_of`
and the CMS entry points, and routed PDF fills and RGB/CMYK image conversion
through them. The wide linear ProPhoto hub avoids sRGB gamut clipping; relative
colorimetric alone remaps black points. Removed the old patch's unused one-step
transform variant. Generic/device spaces retain their existing fallback.

Tests: restored `icc_cmyk_converts_into_another_icc_cmyk_directly` using profiles
generated by the code, plus `direct_cmyk_compensation_only_remaps_relative_black`
for BPC, white, intent/cache separation and rejecting a non-CMYK destination.
Previous-run validation: `cargo test -p vectorcraft-color -p vectorcraft-pdf` passed (118 colour and 320 PDF unit tests, plus integration tests); the added BPC test passed separately. `cargo xtask ci` then passed all nine gates, including 119 colour tests. A first CI attempt hit sandbox socket restrictions; the rerun used local socket access. The new test initially assumed a saturation table; it now explicitly checks the generated profile’s unsupported-intent fallback.

## 2. Non-sRGB PDF tags — f1f35863

**Ported and adapted.** Tagged RGB keeps its working/destination numbers and
profile; decoded RGB images convert into that space, and the writer's RGB
colour/blending profile streams are retagged. PDF/A retains its sRGB fallback.
BPC now affects only relative colorimetric RGB transforms. Unlike the old patch,
the colour tag and matching output intent share one profile stream; a different
sRGB output intent must not reuse a stream being retagged. The existing
`preserveSource` refusal for non-sRGB tagging remains: decoded image conversion
is outside that mode's promise.

Tests: restored `tagged_rgb_in_a_wide_space_keeps_its_numbers_and_embeds_its_profile`
using 0.12's fractional writer output, with same/different output intents,
no-catalog tagging, loaded RGB profiles, image readback and PDF/A checks. Restored
the perceptual BPC assertion in the colour tests.

## 3. PNG colour declaration — b4f7f61f

## 4. PDF-compatible .ai crop — 10b56b9c

**Ported as the local print policy.** PDF import applies CropBox clipping to
PDF-compatible `.ai` artwork as well as ordinary PDFs. This intentionally differs
from upstream's off-artboard editing policy; native editing-data restoration is
unchanged. Adapted the layer/path-count, page-spacing and text-stroke tests rather
than importing the old patch's two test ignores. Added a distinct CropBox versus
MediaBox regression. All PDF inputs are synthetic.

## 5. Preferred units on open — f3cbafb4

**Ported.** Renamed `Loaded::with_grid_prefs` to `with_prefs`, retaining 0.12's
resolved-links argument. Both open and revert apply preferred units when the
importer supplies no explicit unit. Native/restored documents and explicitly
unit-sized SVGs retain their units; geometry is not rescaled.

Tests: restored PDF, pixel SVG, inch SVG and native reopen cases, added explicit
SVG points and embedded-native PDF preservation. The SVG size check allows its
parser's existing floating-point rounding.

## 6. Compound insets — 0a8a0513

**Ported with original synthetic tests.** Face probes exclude directly nested
holes and consider up to eight interior spans before dropping an outline.
`try_offset_path` distinguishes invalid/unresolvable input from a genuinely empty
inset; `offset_path` retains its previous convenience fallback.

The historical test explicitly identifies its coordinates as customer-derived;
those coordinates were not copied. `tests/df_inset.rs` instead constructs a square
with a thin counter, checks several neighbouring inset distances, and tests the
fallible API versus a consumed inset. With only the old probe logic temporarily restored, the synthetic counter test fails (9,984 area becomes zero at -0.28); with the port it passes. The fixed code was restored before final validation.

## 8. Fira Sans Extra Condensed — 0543b4b2

**Adapted to the existing gate-compliant runtime loader; host delivery remains.**
The original font-binary/include-bytes patch is not portable under the repository
font policy. 0.12 already has a clean alternative: `crates/text/web-fonts.txt`,
`crates/text/build.rs`, `xtask/src/web_fonts.rs`, and
`apps/vectorcraft-web/src/fonts.rs`. Added Regular, Medium, SemiBold and Bold as
**startup** faces. Startup fetches finish before the editor and bridge `ready`;
font data is registered with the Rust `FontDb`. No new binary assets or CI
exceptions were added.

Recommended deployment: add the four licensed faces and OFL attribution to
craft-fonts if absent, pin that checkout in the host's build, set an absolute
`CRAFT_FONTS_DIR`, and run the normal Trunk build/post-build hook. The hook copies
the fonts and licences to content-addressed `fonts/<sha16>/` URLs; fetches check
SHA-256 SRI. Deploy those files with the matching WASM. Without the checkout or
manifest entries this remains a warning/no-op; fetch failure also logs and skips.
The host must verify the four faces load before qualifying guide-label layout.
No craft-fonts input was supplied for these checks and no host deployment was
performed, so actual Fira loading and guide-label fidelity remain unverified.
Updated the existing startup-font test to include Fira by family and style;
its old Noto-only expectation would fail once a checkout supplied Fira.

Other options considered:

- **Host-provided bytes through the embed protocol:** feasible using
  `FontDb::add_font`, but needs a new bounded, same-origin message, acknowledgement
  and an open-after-fonts sequence. The current bridge has no font message. It is
  more work than the existing static-host loader and is not implemented here.
- **CSS web fonts alone:** insufficient; Rust shaping/export uses `FontDb`, not
  the browser's CSS font registry.
- **Fork-only CI exception:** would preserve the old embedded-font approach but
  violates the current no-new-font-assets policy and increases WASM size. Not
  implemented or recommended while the existing runtime path is available.
